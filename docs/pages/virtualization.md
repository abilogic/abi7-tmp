# Virtualization

Виртуализация позволяет показывать десятки тысяч карточек, держа в DOM только несколько десятков. Она **не зависит от layout**: получает готовую геометрию и решает, какие индексы нужно смонтировать.

:::demo virtualization

## Как это работает

1. Layout записал координаты всех карточек в `GeometryStore`; по ним построен пространственный индекс.
2. Окно просмотра = `[scrollTop − overscan, scrollTop + высота + overscan]` (по главной оси layout) и аналогично по поперечной.
3. Индекс возвращает карточки, пересекающие окно, — без обхода всех записей и без `getBoundingClientRect()`.
4. Renderer сравнивает результат с DOM: лишние узлы убираются в **DOM Pool**, недостающие берутся из пула или создаются.
5. Прокрутка обрабатывается пассивным слушателем и **один раз за кадр** (`requestAnimationFrame`) — тяжёлых вычислений на каждое событие `scroll` нет.

Проверка: `grid.getState().virtualization` показывает реальное число смонтированных элементов, размер пула и счётчики `created` / `reused`. В примере выше все цифры читаются из этого состояния и из DOM, а не заданы заранее.

## Большие массивы

На 50 000 карточек раскладка считается за единицы миллисекунд, в DOM остаётся порядка 30–60 узлов. Тест в репозитории прокручивает 50 000 записей по 30 позициям и проверяет, что `created` остаётся небольшим, а `reused` растёт.

```js
const grid = new ABI7Grid('#g', { data: fiftyThousand, virtualization: { overscan: 400 } });
console.log(grid.getState().virtualization.mounted);   // десятки, а не 50 000
```

## Overscan и Adaptive Overscan

`overscan` — запас в пикселях за пределами окна. Больше запас — реже пустые места при быстром скролле, но больше DOM-узлов.

`adaptiveOverscan: true` (по умолчанию): ядро считает сглаженную скорость прокрутки и добавляет к запасу в сторону движения `скорость (px/мс) × 300 мс`, но не больше `maxOverscan`. В покое запас возвращается к `overscan` (событие `scroll:stop`). Текущие значения: `getState().virtualization.overscan` → `{ before, after }`.

## DOM Pool

Карточка вышла из окна — её узел не уничтожается: он убирается из документа и откладывается в пул (до `poolSize` штук). Когда в окно входит новая запись, узел берётся из пула и **привязывается** к ней (`renderItem` или стандартная карточка обновляет `<img>` и подпись). Размонтирование выполняется до монтирования, поэтому при прокрутке почти все узлы переиспользуются. Счётчики `created` и `reused` в `getState()` показывают эффективность пула.

Следствия для вашего кода:

- Не храните ссылки на `event.element`, `getItem().element` — узел может показывать другую запись.
- Любую дополнительную разметку внутри карточки ставьте на событие `item:mount` и убирайте на `item:unmount`.
- Классы, назначенные через `api.renderer.toggleClass(id, cls)`, привязаны к id записи и возвращаются элементу автоматически.

## Scroll Anchoring

Если геометрия меняется выше окна (вставка записей, ресайз, смена настроек), содержимое под глазами не должно «прыгать». Перед изменением ядро запоминает **первую видимую карточку и её смещение** от верхнего края окна, а после перерасчёта возвращает её на то же место. Нативный `overflow-anchor` отключён, чтобы браузер не конкурировал с ядром. При `scrollTop = 0` якорь не применяется — новая карточка видна сразу. Отключается опцией `scrollAnchoring: false`.

## scrollToIndex

```js
grid.scrollToIndex(25000, { align: 'center' });
```

Координаты берутся из геометрии: DOM для 25 000 промежуточных карточек не создаётся. Ось (вертикальная или горизонтальная) определяет layout.

## Pinned Items

Закреплённая карточка остаётся в DOM даже вне окна. Ядро использует это при перетаскивании (иначе автопрокрутка уничтожила бы перетаскиваемый узел), а плагины — через `api.viewport.pin(id)`.

## Dynamic Size Cache

Если высота карточек определяется содержимым (`renderItem` с текстом), включите `virtualization.measure: true`. Ядро наблюдает видимые карточки через ResizeObserver, сохраняет измеренные высоты в кэше по id и перестраивает геометрию с изменившейся карточки (частичный перерасчёт + Scroll Anchoring). До измерения используется `estimatedHeight`. Измерения сходятся за один-два прохода: пока измеренная высота совпадает с геометрией, перерасчёта нет, поэтому бесконечных циклов нет.

```js
new ABI7Grid('#g', {
  data: posts,
  layoutOptions: { aspectRatio: 0 },
  virtualization: { measure: true, estimatedHeight: 160 },
  renderItem(post, el) { el.textContent = post.text; }
});
```

## Отключение

`virtualization: { enabled: false }` монтирует **все** карточки — допустимо для небольших наборов (до пары сотен), удобно для печати и тестов.

## Что вызывает перерасчёт, а что нет

| Действие | Перерасчёт геометрии | Обновление DOM |
|---|---|---|
| Прокрутка | нет | да (по индексу) |
| Изменение высоты контейнера | нет (кроме горизонтальных layout) | да |
| Изменение ширины контейнера | полный | да |
| `insert` / `remove` / `move` | частичный (с позиции) | да |
| `update` с изменением размеров | частичный | да |
| `update` прочих полей | нет | только эта карточка |
